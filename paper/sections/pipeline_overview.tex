\section{Pipeline Overview}
\label{sec:pipeline-overview}

The system is a six-stage pipeline. \textbf{Ingestion} registers a source PDF
and its provenance. \textbf{Extraction} recovers text blocks with their page
numbers and page coordinates, using a hybrid of OCR and the PDF's own text
layer, since either alone is unreliable on the multi-column and tabular layouts
these documents favor. \textbf{Detection} is where structure is recovered: it
infers the document's depth map and then classifies every element against it,
emitting a flat list of typed elements, each carrying a level, a code, a title,
an optional description, an age band, and the source text it was read from.
\textbf{Parsing} resolves that flat list into the canonical schema of
\S\ref{sec:schema}, attaching each indicator to its full ancestry and composing
its identifier. \textbf{Validation} checks each record against the schema and
against structural invariants on the identifier, and \textbf{persistence}
writes the surviving records to a relational store.

Two things about this decomposition matter for what follows. First, detection
and parsing are separate stages with separate prompts and separate models,
rather than one prompt that reads a page and emits normalized records; the
rationale is in \S\ref{sec:method-two-stage}. Second, the interface between
them is a flat element list rather than a tree, which is what allows detection
to be evaluated on its own --- against its own golden annotations --- without
the parser's ancestry resolution confounding the measurement. The two
evaluation suites in \S\ref{sec:experiments-results} grade the two stages
independently against separately annotated goldens for exactly this reason.

that lets the method run over whole standards documents.
