## 4. Whole-document single-prompt arm — ✅ FRAMEWORK BUILT, PILOT RUNNING

**It makes the paper, and by a better argument than expected.** Three things:

1. **California is lost entirely, and the failure is categorical.** The single
   call emitted **exactly 16,000 output tokens** — `detector.LLM_MAX_TOKENS` —
   truncating the JSON mid-object so nothing parsed: **0 of 25** golden elements
   against the chunked method's 25/25. One prompt has one output budget for the
   whole document, so overflow loses the *document*; chunking bounds it to a
   *chunk*. ⚠️ **AZ was within 11% of the same cliff** (14,292/16,000) and scored
   1.000 — so a success here does not predict the next document, and the margin
   is invisible in the score.
2. **Where the repairs go, code accuracy goes.** KY 44/44 → 28/44 and TX 8/8 →

   abbreviation rule (`MFAAA`/`MFAAD`, `WPSDS`/`PSDSP`) — the same 25% churn

   Python — plus the missing de-label repair. TX's three are missing anchoring.
   Each is a different Aurora primary key for the same standard.
3. **It is not a strawman.** AZ and NV score 1.000 with full code accuracy and
   no depth map, chunking or repairs. NV — the held-out canary whose namespace
   skips a level — comes back 46/46. Say so plainly; it is what makes findings 1
   and 2 credible.

⚠️ **Code accuracy is over matched pairs only.** CO's arm figure `3/3` covers
three of seven golden elements and must never be printed beside `7/7`
unqualified. AZ/KY/NV/TX denominators *are* comparable.
